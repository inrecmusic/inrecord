# 教室右側單元欄：展開式清單（取代 icon 版）

日期：2026-08-29
狀態：設計定案，待實作
取代：`2026-08-28-classroom-sidebar-content-icons-design.md`（右側 icon 版，已實作但改方向）

## 為什麼改

前一版在單元標題右側放四顆 emoji icon 表示「這個單元有什麼」。實作完成並通過驗收後，使用者提出更根本的目標：**要讓學員感覺「內容很多、物超所值」**。

icon 版只表達「有／沒有」。一個單元有 1 份講義還是 5 份，看起來完全一樣——正好把最想讓學員看見的東西藏了起來。要傳達份量，得讓「量」與「內容本身」可見。

使用者選定：**展開式清單（手風琴）**，icon 沿用前一版已實作的 emoji（不換成線條 SVG）。

## 設計

### 1. 單元列：手風琴展開

- 點單元＝**切換影片 ＋ 展開內容**，一個動作到位。
- **一次只開一個**：切到別的單元時舊的自動收起。21 個單元全展開會讓側欄無法掃視，這條是必要約束。
- 正在上的單元預設展開。
- 收合時在時長旁顯示淡色計數「6 項」，不展開也知道有料。
- 側欄寬度維持 `360px`（桌機）／`min(380px, 88vw)`（平板抽屜）。標題維持兩行 clamp。

### 2. 展開內容：真實項目名稱

展開後列出該單元的實際項目，而非抽象類別：

```
📄 和弦表速查            講義
♪  小星星（簡易版）       樂譜
♪  小星星（進階版）       樂譜
🎮 音符找找看            遊戲
✎  拍手位照片上傳         作業
```

「小星星（簡易版）」比「樂譜」兩個字有份量得多，這是本次改版的核心價值。

點擊行為：

| 項目 | 行為 |
|---|---|
| 講義／樂譜 | 直接開下載（沿用現有簽名 URL 流程） |
| 互動遊戲 | 切到「互動遊戲」分頁並選中該遊戲 |
| 作業 | 切到「作業繳交」分頁 |

### 3. icon：沿用既有 emoji

維持前一版已實作的 emoji，不改圖形也不改對應關係：

| 類型 | icon |
|---|---|
| 講義 | 📎（與播放器下方「📎 講義下載」區塊同一顆，點了捲過去對得起來） |
| 樂譜 | 🎼 |
| 互動遊戲 | 🎮 |
| 作業 | 📝 |

順序固定：📎 → 🎼 → 🎮 → 📝（先看的、再練的、最後交的）。

**在展開清單中不加圓底**——原本圓底是為了讓 icon 在標題右側成為可點的按鈕；展開清單裡整列本身就是點擊目標，圓底反而多餘且吵。`UNIT_ICONS` 常數與 emoji 對應表原樣沿用。

### 4. 「預計 9/30 上架」

課程大綱已全部建入（12 章），但多數單元尚無影片。要讓學員看到完整大綱又不踩到空播放器：

- **沒有 `bunny_video_id` 的單元**：標題下方顯示灰字「預計 9/30 上架」，整列不可點播放（但若該單元已有講義／樂譜，仍可展開下載）。
- **沒有任何單元的章節**：章節標題仍顯示，底下一行灰字「單元準備中，預計 9/30 上架」。需移除 `app/classroom/watch/page.jsx` 目前的 `if (!cv.length) return null`。
- 日期字串集中一處常數，之後改期只改一個地方。

### 5. 頂部課程總覽統計

側欄頂端一行：

```
本課程共 21 支影片 · 27 份講義 · 24 份樂譜 · 15 個互動遊戲 · 11 份作業
```

直接回應「物超所值」——總量一目了然。資料 bootstrap 已全部具備，加總即可，不需新 API。此區塊與單元列完全獨立，日後要拿掉只是刪一個區塊。

## 資料層改動

前一版的後端**幾乎全部沿用**，只有一處換形狀。

### 沿用（已實作並驗收通過，不動）

- `materials.kind` 欄位（`'handout' | 'score'`，帶 DEFAULT）
- 後台 `MaterialsManager` 的類型選單
- 兩支 materials API 讀寫 `kind`
- `bootstrap` 在 `Promise.all` 加的兩個輕查詢，含 `games` 的 `.not("is_active","is",false)` 過濾
- 教室講義區依 `kind` 拆講義／樂譜兩組＋錨點（點展開項下載時仍可用）

### 換形狀

`lib/unit-content.js` 的 `buildContentFlags` 從「回布林旗標」改為「回項目明細」：

```js
// 舊：{ [video_id]: { handout: true, score: false, game: true, assignment: true } }
// 新：{ [video_id]: [{ kind, id, title }, ...] }（已依 講義→樂譜→遊戲→作業 排序）
```

- `materials` 查詢改撈 `id, video_id, kind, title`
- `games` 查詢改撈 `id, video_id, title`
- 作業由 `videos.assignment_desc` 推出一筆 `{ kind: 'assignment', id: video_id, title: '作業繳交' }`
- 總覽統計由同一份明細加總得出，不另外查

**成本評估**：21 單元 × 平均 4 項 ≈ 84 筆，每筆只有 id／標題／類型，回應大小仍可忽略。維持「前端零新增請求」。

## 不做

- 不改 `games` / `videos` 資料表結構
- 不改狀態圈、進度條、章節標題樣式
- 不動 `/classroom` 儀表板（它本來就會列出空章節）
- 不做展開項的數量角標（真實名稱已經表達份量）
