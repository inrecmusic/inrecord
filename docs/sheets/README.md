# 訂單同步到 Google 試算表：設定說明

後台「訂單管理」有一顆同步按鈕，按下去會把訂單寫進你指定的 Google 試算表。
試算表這一端要先做一次設定（大約 10 分鐘），之後就不用再碰了。

- 程式碼：同資料夾的 `orders-sync.gs`
- 資料只會寫進一個叫 **「InRecord 訂單」** 的分頁；**同一份試算表裡其他分頁完全不會被動到**
- 以**訂單編號**為唯一鍵：同一筆訂單重複同步只會更新那一列，不會長出重複列，所以月底重跑、退款後再跑都安全

---

## 一、一次性設定

### 步驟 1：打開 Apps Script 編輯器

1. 用瀏覽器打開你要記帳的那份 Google 試算表
2. 上方選單點 **擴充功能 → Apps Script**
3. 會跳出一個新分頁，這就是編輯器

### 步驟 2：貼上程式碼

1. 編輯器中間那一大塊程式碼（預設是 `function myFunction() {}`）**全選刪掉**
2. 把 `orders-sync.gs` 的內容**整份複製貼上**
3. 按上方的 💾 儲存圖示（或 `Ctrl/⌘ + S`）
4. 左上角專案名稱可以改成「InRecord 訂單同步」，比較好認

### 步驟 3：產生一組密鑰

密鑰是一串只有你和 InRecord 網站知道的隨機字串，用來確認「來要求寫入的人是自己人」。

1. 在編輯器上方的函式下拉選單選 **`generateSecret`**
2. 按 **執行**
3. 第一次執行會要求授權，照著步驟 5 的授權說明點下去
4. 下方「執行記錄」會出現一行 `SHEET_SYNC_SECRET = xxxxxxxx...`
5. 把等號後面那串**複製起來貼到記事本**，等一下兩個地方都要用

> 也可以自己想一組，但請至少 32 個字元、英數混合，不要用生日或常見單字。

### 步驟 4：把密鑰存進指令碼屬性

密鑰不寫在程式碼裡，寫在 Google 的設定區，比較安全。

1. 編輯器左側點 **⚙️ 專案設定**
2. 捲到最下面「指令碼屬性」，點 **新增指令碼屬性**
3. 屬性名稱填：`SHEET_SYNC_SECRET`（**大小寫要完全一樣**）
4. 值：貼上步驟 3 那串密鑰
5. 按 **儲存指令碼屬性**

### 步驟 5：部署成網頁應用程式

1. 編輯器右上角點 **部署 → 新增部署作業**
2. 左邊齒輪「選取類型」選 **網頁應用程式**
3. 說明隨便填，例如「訂單同步 v1」
4. **執行身分：我（你的 Google 帳號）**
5. **具有存取權的使用者：知道連結的任何人**
6. 按 **部署**

第一次部署會要求授權：

- 出現「需要授權」→ 點 **授予存取權**，選你的 Google 帳號
- 若出現「Google 尚未驗證這個應用程式」→ 點左下角 **進階 → 前往「專案名稱」(不安全)**
  （這是自己寫給自己用的程式，Google 對未送審的程式一律這樣顯示，屬正常現象）
- 最後點 **允許**

### 步驟 6：複製網址

部署完成的畫面會出現一段 **網頁應用程式網址**，長得像：

```
https://script.google.com/macros/s/AKfycb.................../exec
```

點 **複製**，一樣先貼到記事本。

### 步驟 7：確認部署成功

把剛剛那個網址**直接貼到瀏覽器網址列打開**，畫面應該出現類似這樣的一行字：

```json
{"ok":true,"service":"inrecord-orders-sync","version":"1.0.0","sheet":"InRecord 訂單","secret_configured":true,"time":"2026-09-12 14:30:00"}
```

- 看到 `"ok":true` → 部署成功
- `"secret_configured":true` → 密鑰有設定好（`false` 的話回頭檢查步驟 4 的屬性名稱有沒有打錯）
- 看到登入畫面或「找不到網頁」→ 回步驟 5 確認「具有存取權的使用者」有沒有選「知道連結的任何人」

### 步驟 8：把網址和密鑰交給工程師

把這兩樣傳給我，我會設進 Vercel 環境變數，後台按鈕才會亮起來：

| 環境變數 | 內容 |
| --- | --- |
| `SHEETS_WEBHOOK_URL` | 步驟 6 的網頁應用程式網址 |
| `SHEETS_WEBHOOK_SECRET` | 步驟 3 的密鑰 |

> 這兩個沒設定之前，後台按鈕會顯示「未設定」，其他功能一切照常，不會出事。

## 二、日常使用

1. 到後台 **訂單管理**
2. 選好月份，按同步按鈕
3. 回試算表看「InRecord 訂單」分頁

分頁欄位順序固定如下（最後一欄是程式自動填的同步時間）：

| A | B | C | D | E | F | G | H |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 訂單編號 | 成立日期 | 付款日期 | Email | 姓名 | 方案 | 金額 | 優惠碼 |

| I | J | K | L | M | N | O | P |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 折抵 | 付款方式 | 狀態 | 發票號碼 | 來源 | 退款日期 | 退款金額 | 同步時間 |

日期都是**台灣時間**，格式 `2026-09-01 10:05`，要篩月份直接用篩選器搜尋 `2026-09` 就好。

### 使用上的小規矩

- **A 到 P 欄由程式維護**，手動改了下次同步會被蓋回去；也不要在這些欄位放公式
- 要自己加備註，請寫在 **Q 欄之後**，同步不會動到那些欄位
- 想換排序、上色、凍結欄位都沒問題，程式只認 A 欄的訂單編號
- 單次最多同步 2000 筆，超過請分月同步

---

## 三、重要：改過程式碼要重新部署

**這是最容易踩到的雷。** 在編輯器裡改完程式碼按儲存，線上的網址還是跑舊版，必須：

1. 右上角 **部署 → 管理部署作業**
2. 找到現有的那筆，點右上角的 **✏️ 鉛筆（編輯）**
3. 「版本」下拉選 **新版本**
4. 按 **部署**

這樣網址不變、直接生效。
（如果改用「新增部署作業」，會產生**另一個新網址**，舊網址還是舊版，那就得回頭更新 Vercel 環境變數，麻煩很多。）

## 四、疑難排解

| 狀況 | 原因與解法 |
| --- | --- |
| 後台顯示「未設定」 | Vercel 兩個環境變數還沒設，或設完沒重新部署，找工程師 |
| 回應 `unauthorized` | 密鑰對不上：指令碼屬性和 Vercel 環境變數不是同一組，重新確認兩邊 |
| 回應 `not_configured` | 指令碼屬性 `SHEET_SYNC_SECRET` 沒設或名稱打錯（步驟 4） |
| 回應 `busy` | 上一次同步還在跑，等幾秒再按一次 |
| 回應 `too_many_orders` | 一次超過 2000 筆，改成分月同步 |
| 回應 `missing_order_no` | 有訂單沒有訂單編號，把錯誤訊息截圖給工程師 |
| 改了程式沒效果 | 忘了用「新版本」重新部署，看上面第三節 |
| 分頁被不小心刪掉 | 不用擔心，下次同步會自動重建分頁和表頭，但先前的資料要重新同步一次 |
| 密鑰不小心外流 | 重跑 `generateSecret` 產生新的，更新指令碼屬性，並把新密鑰給工程師更新 Vercel |

> 部署網址請當成密碼看待，不要貼到公開的地方。即使外流，沒有密鑰也寫不進試算表。

## 五、給工程師：介面規格

**請求** `POST <SHEETS_WEBHOOK_URL>`，`Content-Type: application/json`
（Apps Script 會 302 轉址到 `script.googleusercontent.com`，`fetch` 預設會跟隨，不要關掉 redirect）

```json
{
  "secret": "SHEETS_WEBHOOK_SECRET",
  "orders": [
    {
      "mer_trade_no": "INREC1782785571389",
      "created_at": "2026-09-01 10:00",
      "paid_at": "2026-09-01 10:05",
      "email": "student@example.com",
      "name": "王小明",
      "plan": "bundle",
      "amount": 5500,
      "coupon_code": "FAN3999",
      "discount": 500,
      "pay_type": "CREDIT",
      "status": "paid",
      "invoice_no": "AA26522751",
      "source": "payuni",
      "refunded_at": "",
      "refund_amount": ""
    }
  ]
}
```

- `mer_trade_no` 必填，是 upsert 的唯一鍵；同一批內重複會以最後一筆為準
- 日期欄位送 `yyyy-MM-dd HH:mm`（台灣時間）最準；送 ISO 8601 字串也可以，Apps Script 端會轉成台灣時間
- 金額欄位送數字；沒有值就送 `""` 或省略，表格會留白（不會寫成 0）
- 未列出的欄位會留白，多送的欄位會被忽略

**回應**（Apps Script 一律回 HTTP 200，成敗看 `ok`）

```json
{ "ok": true, "inserted": 12, "updated": 58 }
```

```json
{ "ok": false, "error": "unauthorized" }
```

錯誤碼：`bad_request`、`not_configured`、`unauthorized`、`invalid_orders`、`too_many_orders`、`missing_order_no`、`busy`、`internal_error`。

**健康檢查** `GET <SHEETS_WEBHOOK_URL>` 回 `{ ok, service, version, sheet, secret_configured, time }`，不含密鑰。

Apps Script 端的純邏輯（欄位順序、upsert、防呆）有測試：

```bash
npx vitest run docs/sheets/orders-sync.test.js
```
